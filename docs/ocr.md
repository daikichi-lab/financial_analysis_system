# 決算書の読み取り

`② 数値入力` タブの「決算書を読み込む」から、PDF・画像（スキャン／写真）・Excel(.xlsx)・CSV を渡せます。
前期と当期が並んだ比較形式なら複数期をまとめて取り込みます。上限20MB、`.xls`（旧形式）は未対応。

- 読み取った科目は**まとめずに1行ずつ**明細へ入ります
- FPが確認して「分析する」を押すまで分析には進みません
- 対応先が決まらなかった科目は色を変えて明示します（金額は保持、分析には入らない）
- 貸借不一致、決算書の合計と明細の食い違い、判読不能箇所は警告として一覧表示します
- 元ファイルと抽出結果は履歴として保存されます

## エンジンの選択

`.env` の `OCR_ENGINE`。既定は **無料エンジン**（`free`）で、API費用はかかりません。

| 入力 | 無料エンジンの処理 | 精度 |
|---|---|---|
| PDF（会計ソフト出力・テキスト層あり） | ローカルで文字を直接取得 | 高い |
| Excel(.xlsx) / CSV | ローカルで解析 | 高い |
| スキャンPDF・写真 | Tesseract（日本語） | 誤読が起きやすい |

精度が足りない場合は `OCR_ENGINE=claude` で有料エンジンに切り替わります。

> **注意** — 有料エンジンは内部項目に寄せた形で返すため、**決算書の科目名そのままの明細は保持されません**。
> 科目名まで残したい場合は無料エンジンをお使いください。

### 無料エンジンの仕組み

```
ファイル
  ├ PDF（テキスト層あり） → pdfjs で位置つきテキストを取得
  ├ PDF（スキャン）      → ページを画像化 → Tesseract
  ├ 画像                → Tesseract
  └ Excel / CSV         → 直接解析
        ↓
  行構造（ラベル＋位置つき数値）
        ↓  金額の列を検出して期に割り当て
        ↓  account_map で科目名 → 内部キー
  明細行（source_label と map_key は別フィールド）
```

- 単位は「単位：千円」などの表記から自動判定
- 期は「第41期」「前期／当期」「令和6年3月期」などの見出しから検出
- 「〜合計」で終わる行は小計として区別し、内訳との二重計上を防ぎます
- セクション見出し（貸借対照表／製造原価報告書／販管費明細 など）を追跡し、
  「減価償却費」のような曖昧な科目を製造原価と販管費に振り分けます

### Tesseractについて

初回のみ言語データ（約15MB）をネットワーク経由で取得します。オフライン環境では
`TESSERACT_LANG_PATH` に言語データの場所を指定してください。

スキャン・写真での日本語の表組み読み取りは誤読が起きやすいため、
全項目の確認を前提にしてください。精度が実用に足りない場合は有料エンジンへの切り替えをご検討ください。

## 有料エンジンのモデルと effort

`OCR_ENGINE=claude` のときのみ有効。既定は `claude-sonnet-5` / `effort=medium`
（`.env` の `OCR_MODEL` / `OCR_EFFORT`）。

この処理は表から決まった項目を書き写す作業で、勘定科目の寄せ方はシステムプロンプトに
明記してあるため、モデルが自力で考える余地は多くありません。高い設定にしてもコストの大半が
「読み直しの思考トークン」に消えるだけになりがちです。誤読は未対応科目の明示と
貸借一致チェックでFPが受け止める設計なので、まず安い設定から試すのが妥当です。

判読しにくい書類で精度が足りない場合だけ上げてください。

    モデル: claude-sonnet-5 → claude-opus-5
    effort: low → medium → high

### 費用の目安

| 設定 | 1件の目安 |
|---|---|
| 無料エンジン | **0円** |
| claude-sonnet-5 / medium | 約15〜30円 |
| claude-opus-5 / high | 約25〜70円 |

1ドル150円換算。ページ数と書類の判読しやすさで大きく変わります。

### どこまで安くできるかを実測する

```bash
npm run ocr:compare -- ./手元の決算書.pdf
```

同じ決算書を4通りの設定で読み取り、**コスト・所要時間・抽出値の一致率**を並べて表示します。
設定によって値が食い違った項目には `▲` が付くので、そこだけ決算書と照合すれば
「安い設定で足りるか」を推測ではなく実測で判断できます。最後に推奨設定を出力します。

実運用中のコストは管理画面 →「利用状況」に1件ずつ記録されます。

    決算書の読み取り  kessan.xlsx / 2期 27行 / 未対応1件 / free / 約$0.000 / 0.0秒

## 読み取り履歴

読み取りのたびに、**送信元ファイルそのものと抽出した全項目・警告**を `ocr_imports` に保存します。
管理画面 →「読み取り履歴」で、対応先が付かなかった科目も含めて全行を確認でき、
元ファイルもダウンロードできます。

元ファイルを保存したくない場合は `.env` に `OCR_KEEP_FILE=0` を設定してください（抽出結果のみ保存）。

## 精度を上げるには

1. **会計ソフトのCSV/Excelを使う** — テキストなので最も確実です。弥生会計の試算表エクスポートはそのまま取り込めます
2. **未対応科目を紐付ける** — 管理画面「科目マッピング」で対応先を決めると、次回から自動で入ります
3. **補足情報を渡す** — 「単位は千円」「製造原価報告書は3ページ目」など
4. **有料エンジンに切り替える** — スキャン中心の運用で無料エンジンの精度が足りない場合
